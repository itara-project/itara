# ADR 0006 — Fat Pointer Tuple for Cross-Boundary Trait Casting in Rust

**Date:** May 2026  
**Status:** Accepted  
**Applies to:** Rust implementation only

## Context

The Itara registry stores components as `Box<dyn ItaraComponent>` — a type-erased representation that allows any component to be stored uniformly. When a caller requests a component via `registry.get::<dyn CalculatorService>("calculator")`, the registry must cast the stored type-erased component to the requested trait object.

The initial implementation used `*const ()` (a single pointer) to store the cast result from `cast_to()`, with `std::mem::transmute_copy` to reconstruct the trait reference. This approach crashed at runtime on Windows with:

```
cannot transmute_copy if Dst is larger than Src
```

The root cause: a `*const dyn Trait` is a fat pointer — 16 bytes on all platforms (data pointer + vtable pointer). Erasing it to `*const ()` (8 bytes) silently discarded the vtable pointer, making reconstruction impossible.

## Decision

`cast_to()` returns `Option<(*const (), *const ())>` — a tuple preserving both words of the fat pointer. The `reconstruct_ref()` function takes the tuple and uses `transmute_copy` to recover the original fat pointer including its vtable.

```rust
fn cast_to(&self, trait_id: TypeId) -> Option<(*const (), *const ())> {
    if trait_id == TypeId::of::<dyn CalculatorService>() {
        let fat = self as &dyn CalculatorService as *const dyn CalculatorService;
        Some(unsafe { std::mem::transmute(fat) })
    } else {
        None
    }
}

unsafe fn reconstruct_ref<T: ?Sized + 'static>(fat: (*const (), *const ())) -> &'static T {
    let fat_ptr: *const T = std::mem::transmute_copy(&fat);
    &*fat_ptr
}
```

The `transmute` of `*const dyn Trait` → `(*const (), *const ())` is sound because fat pointers are exactly two pointer-sized words on all Rust platforms. This is a documented property of the Rust memory model.

## Consequences

- The registry correctly returns `&dyn CalculatorService` without the caller naming the concrete type. The gateway calls `registry.get::<dyn CalculatorService>("calculator")` and receives a trait object, whether the underlying implementation is a local struct or an HTTP proxy.
- The unsafe surface is contained to `cast_to()` impls (one per component) and `reconstruct_ref()` (one function in itara-core). Everything the application touches is safe Rust.
- The `cast_to()` pattern is mechanical and follows a fixed template. It will be generated by a `#[derive(ItaraComponent)]` proc macro, eliminating the boilerplate from component authors entirely.
- This approach works within the same Rust compiler version. Cross-compiler-version fat pointer layout compatibility is not guaranteed by the Rust spec. Components and the agent must be compiled with the same toolchain version. This constraint will be enforced by the metadata file (ADR 0008).
- The single-pointer approach (`*const ()`) must never be used for fat pointer storage. This crash was found on Windows during the initial PoC. The fix is baked into the trait definition — the return type makes the correct approach the only approach.
